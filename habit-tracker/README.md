# Личный трекер привычек

Однопользовательское PWA-приложение: геймифицированный трекер привычек в тематике
гоночного дашборда. День — круг, привычки — контрольные точки, прогресс меряется
личными рекордами. Пропуск гасится «пит-стопом», а не наказанием.

Реализовано по ТЗ `habit-tracker-claude-code-spec.md`.

## Стек

- **Next.js 14** (App Router), React 18, TypeScript
- **Prisma + SQLite** — данные
- **Tailwind CSS** — стили, тёмная тема по токенам раздела 7 ТЗ
- **Recharts** — радар-чарт статов
- **web-push** — вечернее напоминание
- Passcode-защита через middleware (без NextAuth и ролей)

Ни Docker, ни Redis, ни фоновых воркеров: все периодические пересчёты (недельные
бюджеты, стрики за пропущенные дни) выполняются лениво при заходе в приложение.

## Быстрый старт

```bash
cd habit-tracker
npm install
cp .env.example .env
```

В `.env` обязательно задайте два значения:

```bash
APP_PASSCODE="1234"                       # код входа
SESSION_SECRET="$(openssl rand -hex 32)"  # подпись cookie сессии
```

Дальше:

```bash
npm run setup   # prisma generate + db push + seed
npm run dev     # http://localhost:3000
```

### Вечернее напоминание (опционально)

```bash
npm run gen:vapid     # печатает пару ключей — скопируйте в .env
```

После перезапуска включите напоминание в «Настройках». Время отправки задаёт
внешний планировщик, который дёргает эндпоинт:

```bash
curl -X POST https://<хост>/api/push/send \
  -H "authorization: Bearer $PUSH_CRON_SECRET"
```

Подойдёт cron хостинга, systemd-таймер или «Ярлыки» на iPhone. Эндпоинт сам
проверяет, остались ли незакрытые привычки, и молчит, если день закрыт.

### Установка на телефон

Откройте приложение в браузере телефона → «Поделиться» → «На экран “Домой”».
На iOS push-уведомления работают только после добавления на домашний экран.

## Правила игры

Все числовые константы собраны в `src/lib/domain/rules.ts` — их предполагается
тюнить.

- **Уровень**: `floor(sqrt(xpTotal / 50)) + 1`
- **XP**: начисляется за выполненную POSITIVE-привычку; +20% к XP блока, если блок
  дня закрыт целиком
- **Статы**: выполнение добавляет `floor(xpValue / 2)` к своему стату
- **Топливо**: за каждую выполненную привычку + 20% бонус за полностью закрытый день
- **Пит-стопы**: 1 токен за каждые 7 дней подряд, максимум 3 в запасе. При пропуске
  токен списывается, стрик сохраняется; без токенов стрик обнуляется, рекорд
  фиксируется
- **Бюджеты**: сброс в понедельник; неделя в рамках лимита даёт бонус ×5 от
  стоимости привычки. Превышение не штрафуется — просто без бонуса

## Отступления от черновика схемы в разделе 3 ТЗ

Схема в ТЗ помечена как черновик; ниже — что изменено и почему.

1. **`DailyLog.date` — строка `"YYYY-MM-DD"`, а не `DateTime`.** SQLite хранит
   `DateTime` в UTC; «день» при этом расходился бы с локальным днём пользователя на
   границах суток и при переходе на летнее время. Локальная зона задаётся
   `APP_TIMEZONE` в `.env`.
2. **Добавлен `@@unique([habitId, date])` на `DailyLog`.** Без него повторная
   отметка плодила бы дубли строк за один день.
3. **`dayType` вынесен из `DailyLog` в отдельную модель `DayEntry`.** Тип дня —
   свойство дня, а не каждой отдельной отметки; в исходной схеме он дублировался бы
   в каждой строке лога и мог разойтись между ними.
4. **Добавлена `LedgerEntry` — журнал начислений, и `UserStats` стал кэшем поверх
   него.** Начисления пересчитываются по ключу `day:<дата>`, поэтому снятие галочки
   откатывает ровно то, что начислило, даже если формула или бонусы с тех пор
   поменялись. Без журнала накопительные счётчики неизбежно дрейфуют.
5. **Добавлена `BudgetWeek`** — закрытая неделя по антипривычке с фактом выплаты
   бонуса. Делает ленивое закрытие недель идемпотентным: повторный заход не платит
   бонус дважды.
6. **Добавлена `AppState`** — до какой даты посчитаны стрики и какая неделя закрыта
   последней. Это и есть замена cron-джобу (раздел 4.4 ТЗ).
7. **Добавлены `Achievement` и `PushSubscription`** — трофеи из раздела 6.4 и
   подписка на напоминание из раздела 2.
8. **`Streak.daysTowardsPitStop`** — прогресс к следующему пит-стопу, чтобы
   показывать «до пит-стопа N» и не выводить это каждый раз заново.
9. **У `Habit` добавлены `unitLabel`, `dailyBinary`, `sortOrder`, `createdAt`.**
   `dailyBinary` закрывает случай скроллинга и вейпа из раздела 4.4, где отметка —
   «уложился / не уложился» за день, а не счётчик. `createdAt` нужен, чтобы дни до
   заведения привычки не считались пропусками.
10. **`Purchase.nameAtPurchase`** — история покупок не должна ломаться при
    переименовании или удалении награды.

Стрики нигде не мутируются инкрементально: `recomputeStreak` каждый раз
пересчитывает их с нуля по логам. Правка задним числом, смена расписания или отмена
отметки не оставляют рассинхрона.

## Решения, которые стоит знать

- **Тип дня по умолчанию — «Дом».** Если в какой-то прошедший день приложение не
  открывали, этот день считается домашним. Значит, привычки с видимостью «кроме
  офиса» в нём были обязательны и пропуск засчитается — его гасит пит-стоп.
- **Seed-привычки собраны из разделов 4.4 и 5 ТЗ** (в разделе 3 списка привычек нет).
  Это точка старта: всё редактируется в «Настройках».
- **Три награды в seed — примеры.** По разделу 4.5 позиции магазина заводит сам
  пользователь; примеры можно удалить.
- **Архив вместо удаления.** Удаление привычки стирает её историю и пересчитывает
  начисления; архив сохраняет историю и просто убирает привычку из ленты дня.
